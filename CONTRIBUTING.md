# Contributing

Thank you for your interest in contributing to the Tarot Ontology!

Contributions of all kinds are welcome: fixing mistakes, improving the documentation, adding symbols or correspondences, or contributing whole new decks.

Please read the [Design Philosophy](design.md) before making a contribution and remember that tarot is highly subjective - you may make suggestions but it's ultimately the repository owner's choice whether to accept contributions. This is a hobby-project maintained by a single individual, please bear this in mind whilst managing engagement expectations.

For anything beyond a small fix, please open an issue first so we can discuss the change before you do any of the work.

## Getting started

See [DEVELOPING.md](DEVELOPING.md) for setting up the project, running the tests and building the site locally.

Contributions should be submitted through GitHub using the standard fork-and-pull-request workflow. Fork this repository, create a branch for your changes, and commit your work there. Once you're happy with your changes, open a pull request against the main repository, providing a brief description of what you've changed and why.

Please keep pull requests focused on a single change wherever possible, and make sure that any relevant tests pass before submitting. If your contribution relates to an existing issue, please reference it in your pull request so that the discussion and implementation can be kept together.

Pull requests will be reviewed before being merged. We may suggest changes, ask questions, or request further clarification as part of that process.

## Contributing data

**Write all Turtle by hand** in the existing style, and reuse any prefixes already declared in neighbouring files before introducing new ones. Our tests should pick up any data quality issues.

## Use of AI

We are open to the use of AI tools that assist with development, research, and documentation. However, this project is strongly opposed to exclusively AI-generated contributions, sometimes described as vibe coding or slop.

All contributions, regardless of how they were produced, are expected to have been reviewed, understood, and carefully considered by a human. Contributors remain responsible for the accuracy, quality, and provenance of their submissions.

A considerable amount of human time, research, and care has gone into creating this project and we wish to maintain those standards in everything that is contributed to the project in the future.
